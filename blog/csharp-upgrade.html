2. Core Concepts Review - The Building Blocks

2.1 Variables and Data Types (Refresher)

Variables are like labeled boxes where you store information. Here are the main types you'll work with:

  • int: whole numbers (like 5 or -10)
  • double: decimal numbers (like 3.14 or 2.5)
  • string: text (like "Hello" or "Your name")
  • bool: true/false values (like true or false)
int age = 30; double price = 19.99; string name = "Alice"; bool isMember = true; Console.WriteLine($"{name} | {age} years old | Price: {price}");
Quiz 2: Which of these declares a string variable?
string greeting = "Hi";
int greeting = "Hi";
bool greeting = "Hi";

2.2 Getting Input from Users

Interact with users using Console.ReadLine() to get input and Console.Write* to show output:

// Ask for the user's name: Console.Write("Enter your name: "); string userName = Console.ReadLine(); Console.WriteLine("Hello, " + userName + "!");
Quiz 3: Which method reads user input?
Console.Write()
Console.ReadLine()
Console.Input()

2.3 Making Decisions with if/else

Conditionals let your program make decisions based on conditions:

int age = 20; if(age >= 18) { Console.WriteLine("Adult"); } else { Console.WriteLine("Minor"); }
Quiz 4: What does if do?

2.4 Loops - Doing Things Repeatedly

Loops let you repeat code blocks easily without writing the same thing over and over:

// For loop example: for(int i = 1; i <= 3; i++) { Console.WriteLine(i); } // While loop example: int count = 1; while(count <= 3) { Console.WriteLine(count); count++; }

2.5 Methods - Reusable Code Blocks

Methods are like recipes - you write the instructions once and can use them over and over again:

static void Greet(string name) { Console.WriteLine("Hello, " + name + "!"); } Greet("Sam"); // Output: Hello, Sam!

3. Object-Oriented Programming - The Heart of C#

C# is built around object-oriented programming. Think of it as organizing your code like real-world objects:

  • Classes: blueprints for creating objects (like a car design)
  • Objects: actual instances of classes (like your specific car)
  • Properties: data stored in objects (like the car's color)
  • Methods: actions objects can do (like starting the car)
class Car { public string Model; public void Start() { Console.WriteLine(Model + " started!"); } } Car myCar = new Car(); myCar.Model = "Toyota"; myCar.Start(); // Output: Toyota started!
OOP helps organize complex programs into manageable pieces - like building with LEGO blocks!

Encapsulation & Properties - Keeping Data Safe

Encapsulation is like putting your data in a protective box - you control how it's accessed and modified:

public class User { public string Name { get; set; } // auto-property private int age; public int Age { get { return age; } set { if (value >= 0) age = value; else throw new ArgumentException("Age cannot be negative"); } } }

Inheritance and Polymorphism - Building on What Exists

Inheritance lets you create new classes based on existing ones, and polymorphism lets you use them flexibly:

public class Animal { public virtual void Speak() { Console.WriteLine("Animal sound"); } } public class Dog : Animal { public override void Speak() { Console.WriteLine("Woof!"); } } Animal pet = new Dog(); pet.Speak(); // Output: Woof!
Quiz 7: What does virtual do?
Allows derived classes to override a method
Declares a static method
Hides the method from outside

Abstract Classes & Interfaces - Defining Contracts

Abstract classes and interfaces define what classes must do, like a contract or blueprint:

// Abstract class example public abstract class Shape { public abstract double Area(); } public class Circle : Shape { public double Radius { get; set; } public override double Area() => Math.PI * Radius * Radius; }
// Interface example public interface IDrive { void Start(); void Stop(); } public class Car : IDrive { public void Start() { Console.WriteLine("Starting"); } public void Stop() { Console.WriteLine("Stopping"); } }

4. Collections and LINQ - Working with Data Like a Pro

Collections are like smart containers for your data, and LINQ is like having a super-powered search and filter system:

  • List<T> — dynamic arrays that grow and shrink
  • Dictionary<K, V> — key-value pairs (like a phone book)
  • HashSet<T> — collections of unique items
using System.Collections.Generic; using System.Linq; var numbers = new List<int> {1,2,3,4,5,6}; var evenNums = numbers.Where(n => n % 2 == 0).ToList(); Console.WriteLine(string.Join(", ", evenNums)); // Output: 2, 4, 6
Quiz 8: What does Where(n => n % 2 == 0) do?
Sorts the numbers
Filters for even numbers

5. Delegates and Events - Making Your Code Responsive

Delegates are like function pointers, and events let your code respond to things that happen. Think of events like doorbells - when someone rings, you respond:

// Delegate example public delegate void Notify(); public class Process { public event Notify OnDone; public void Run() { Console.WriteLine("Running..."); OnDone?.Invoke(); } }
Delegates allow methods to be passed as parameters, and events notify when actions occur - like having a notification system in your code!

6. Generics - Writing Flexible, Reusable Code

Generics let you write code that works with any type you give it. Think of it like a template that adapts to whatever you need:

public class Box<T> { public T Value { get; set; } } var box = new Box<string>(); box.Value = "Hello Generics!"; Console.WriteLine(box.Value);

7. Exception Handling - Dealing with Problems Gracefully

Exception handling is like having a safety net - when something goes wrong, your program can catch the problem and handle it properly instead of crashing:

try { throw new InvalidOperationException("Oops!"); } catch(InvalidOperationException ex) { Console.WriteLine(ex.Message); } finally { Console.WriteLine("Always runs, good for cleanup."); }

8. Asynchronous Programming - Keeping Your App Responsive

Async programming lets your app do multiple things at once without freezing. It's like being able to cook dinner while doing laundry:

using System.Threading.Tasks; public async Task DownloadAsync() { Console.WriteLine("Starting download..."); await Task.Delay(2000); Console.WriteLine("Download finished."); }
Quick tip: await lets your program continue doing other work while waiting for something to finish.

9. File Handling and Data - Working with Files and JSON

Learn how to read and write files, and work with JSON data. This is essential for most real-world applications:

using System.IO; File.WriteAllText("hello.txt", "Hello, file!"); string content = File.ReadAllText("hello.txt"); Console.WriteLine(content);
using System.Text.Json; public class Person { public string Name { get; set; } } string json = JsonSerializer.Serialize(new Person { Name = "Alice" }); Person deserialized = JsonSerializer.Deserialize<Person>(json); Console.WriteLine(deserialized.Name);

10. Dependency Injection - Writing Better, Testable Code

Dependency injection is like having a smart assistant that provides your classes with the tools they need. It makes your code more flexible and easier to test:

// Simple constructor injection: public class Logger { public void Log(string message) => Console.WriteLine(message); } public class Service { private readonly Logger _logger; public Service(Logger logger) { _logger = logger; } public void Execute() => _logger.Log("Service running..."); } // Usage: var logger = new Logger(); var service = new Service(logger); service.Execute();
Why this matters: Dependency injection makes your code more flexible and easier to test. Learn more about DI | Design Patterns in C#

11. Advanced C# Features - Taking It to the Next Level

11.1 Extension Methods - Adding Features to Existing Classes

Extension methods let you add new functionality to existing classes without modifying them. It's like adding new tools to your toolbox:

public static class StringExtensions { public static int WordCount(this string str) { return str.Split(new char[] { ' ', '.', '?' }, StringSplitOptions.RemoveEmptyEntries).Length; } } // Usage: string text = "Hello world! How are you?"; Console.WriteLine(text.WordCount()); // Output: 5

11.2 Lambda Expressions and Expression Trees

Lambda expressions are like shortcuts for writing methods. They make your code more concise and readable:

// Lambda expressions var numbers = new List<int> { 1, 2, 3, 4, 5 }; var doubled = numbers.Select(n => n * 2); var evens = numbers.Where(n => n % 2 == 0); // Expression trees Expression<Func<int, bool>> expr = num => num < 5; Console.WriteLine(expr.Compile()(3)); // Output: True

11.3 Attributes and Reflection - Metadata and Runtime Information

Attributes add metadata to your code, and reflection lets you examine and work with that metadata at runtime:

[Obsolete("Use NewMethod instead")] public void OldMethod() { } [Serializable] public class Person { public string Name { get; set; } } // Reflection example Type type = typeof(Person); var properties = type.GetProperties(); foreach(var prop in properties) { Console.WriteLine(prop.Name); }

11.4 Memory Management and Garbage Collection

Understanding how C# manages memory helps you write more efficient code:

// Using statement for automatic disposal using (var stream = new FileStream("test.txt", FileMode.Create)) { // File will be automatically closed when we exit this block } // IDisposable pattern public class ResourceManager : IDisposable { public void Dispose() { // Clean up resources Console.WriteLine("Cleaning up resources..."); } }

11.5 Threading and Parallel Programming

Learn how to run code in parallel for better performance:

using System.Threading.Tasks; // Parallel processing var numbers = Enumerable.Range(1, 1000).ToList(); var results = new List<int>(); Parallel.ForEach(numbers, num => { lock(results) { results.Add(num * 2); } }); // Task-based programming var task1 = Task.Run(() => Console.WriteLine("Task 1")); var task2 = Task.Run(() => Console.WriteLine("Task 2")); Task.WaitAll(task1, task2);

11.6 Pattern Matching - Modern C# Features

Pattern matching makes your code more readable and expressive:

// Switch expressions (C# 8.0+) string GetDisplayName(object obj) => obj switch { string s => $"String: {s}", int i => $"Number: {i}", Person p => $"Person: {p.Name}", _ => "Unknown" }; // Property patterns bool IsValidPerson(Person p) => p switch { { Name: not null, Age: >= 18 } => true, _ => false };

11.7 Records - Immutable Data Classes (C# 9.0+)

Records are perfect for data that doesn't change after creation:

// Record declaration public record Person(string Name, int Age); // Usage var person1 = new Person("Alice", 30); var person2 = person1 with { Age = 31 }; // Creates a copy with new age Console.WriteLine(person1); // Person { Name = Alice, Age = 30 } Console.WriteLine(person2); // Person { Name = Alice, Age = 31 }

11.8 Nullable Reference Types - Preventing Null Reference Exceptions

Help prevent null reference exceptions at compile time:

#nullable enable public class User { public string Name { get; set; } = string.Empty; // Must be initialized public string? Email { get; set; } // Can be null } public void ProcessUser(User user) { Console.WriteLine(user.Name); // Safe - Name is never null if (user.Email != null) { Console.WriteLine(user.Email); // Safe after null check } }

Project Example: Advanced TODO List

Here's a more advanced version of a TODO list that uses many of the concepts we've covered:

using System; using System.Collections.Generic; using System.Linq; using System.Threading.Tasks; public class TodoItem { public int Id { get; set; } public string Title { get; set; } = string.Empty; public string Description { get; set; } = string.Empty; public bool IsCompleted { get; set; } public DateTime CreatedAt { get; set; } = DateTime.Now; public Priority Priority { get; set; } = Priority.Medium; } public enum Priority { Low, Medium, High } public class TodoManager { private List<TodoItem> _items = new(); private int _nextId = 1; public event Action<TodoItem>? ItemAdded; public event Action<TodoItem>? ItemCompleted; public async Task AddItemAsync(string title, string description, Priority priority) { var item = new TodoItem { Id = _nextId++, Title = title, Description = description, Priority = priority }; _items.Add(item); ItemAdded?.Invoke(item); // Simulate some async work await Task.Delay(100); } public IEnumerable<TodoItem> GetItemsByPriority(Priority priority) { return _items.Where(item => item.Priority == priority); } public async Task CompleteItemAsync(int id) { var item = _items.FirstOrDefault(i => i.Id == id); if (item != null) { item.IsCompleted = true; ItemCompleted?.Invoke(item); await Task.Delay(100); } } public IEnumerable<TodoItem> GetCompletedItems() { return _items.Where(item => item.IsCompleted); } }
