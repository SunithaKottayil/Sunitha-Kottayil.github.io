Getting Started with Git

By Sunitha Kottayil • January 15, 2025
Creating something cool and useful always means changing things up. Imagine a handy notebook that remembers every version and helps your whole team work smoothly together.

What is Git anyway?

Think of Git as a time machine for your code. Every time you make changes to your project, Git can take a "snapshot" of those changes. If something breaks later, you can easily go back to when everything was working. Imagine you’re playing a video game where you can save your progress anytime. Git is like that save button—it takes a picture of your project each time you make changes. If things go wrong, you can “rewind” back to a point where everything was working perfectly, just like loading a save file in a game! Simple definition: "Git is a tool that saves every change you make to your project, so you can try new ideas safely, fix mistakes easily by going back to previous versions.".

Git is also great for collaboration. Multiple people can work on the same project without stepping on each other's toes.

❌ Without Git
  • project1.zip
  • project_final.zip
  • project_corrected.zip
  • project_latest.zip

Sound familiar?

✅ With Git
  • One project folder
  • Complete history
  • Easy collaboration
  • Never lose work

Much better!

Installing Git

First things first, let's get Git installed on your computer:

  • Windows: Download the installer from git-scm.com and follow the setup steps.
  • Mac: Open Terminal and type git. If Git isn’t installed, you’ll be prompted to install the Xcode Command Line Tools. Alternatively, you can use Homebrew by running brew install git.
  • Linux: Use your package manager to install Git. For example, on Debian or Ubuntu, run sudo apt install git.

To check if it's installed correctly, open your terminal and type:

git --version
Tip: If you see a version number, you're good to go! If not, try restarting your terminal or computer.

Setting up your identity

Before you start using Git, you need to tell it who you are. This information gets attached to your commits:

git config --global user.name "Your Name"
git config --global user.email "your@email.com"
Important: Use the same email that you'll use for GitHub or other Git hosting services.

Your first repository

A repository (or "repo") is just a fancy name for a project folder that Git is watching. Let's create one:

mkdir my-first-project
cd my-first-project
git init

Congratulations! You just created your first Git repository. The git init command creates a hidden .git folder that stores all the Git magic.

The basic Git workflow

Git has a simple three-step workflow:

The Git Workflow

1
Make changes
2
Stage files
3
Commit changes

Let's try it out. First, create a simple file:

"Hello, Git!" > README.md

Now let's see what Git thinks about our new file:

git status

Git will tell you that README.md is "untracked". To start tracking it, use git add:

git add README.md

Now the file is "staged" – ready to be committed. Let's save this snapshot:

git commit -m "Add README file"

Great! You just made your first commit. The -m flag lets you add a message describing what you changed.

Essential Git commands

Here are the commands you'll use most often:

git status
See what's changed in your project
git add .
Stage all changes for commit
git commit -m "message"
Save a snapshot with a description
git log
View your commit history
Pro tip: Use git status frequently. It's like asking Git "what's going on?" and will help you understand what's happening.

Fixing mistakes

Made a mistake? Don't panic! Git has several ways to fix things:

Undo changes to a file (before staging)

git checkout -- filename.txt

Unstage a file

git reset HEAD filename.txt

Undo the last commit (but keep your changes)

git reset --soft HEAD~1
Be careful! Some Git commands can permanently delete your work. When in doubt, make a backup copy of your project first.

Sharing your work with GitHub

Now for the fun part – putting your code online! GitHub is like Dropbox for programmers.

  1. Create a free account at github.com
  2. Click the "+" button and create a new repository
  3. Give it the same name as your local project
  4. Copy the repository URL and run these commands:
git remote add origin https://github.com/yourusername/my-first-project.git
git branch -M main
git push -u origin main

That's it! Your code is now online and backed up. You can view it by going to your repository URL.

Working with others

When working with a team, you'll need a few more commands:

git pull origin main

This downloads any changes your teammates have made.

git push origin main

This uploads your changes for others to see.

Good habit: Always pull before you push. This ensures you have the latest changes before adding your own.

Best practices

  • Commit often: Small, frequent commits are better than huge ones
  • Write good commit messages: "Fix login bug" is better than "fixed stuff"
  • Use .gitignore: Don't commit temporary files or passwords
  • Learn branches: They let you experiment without breaking your main code

What's next?

You now know the basics of Git! Here's what to explore next:

  • Learn about branching and merging
  • Explore GitHub's features (issues, pull requests)
  • Practice with small personal projects
  • Contribute to open source projects
Remember: Git takes practice. Don't worry if it feels confusing at first – every developer went through the same learning curve!
