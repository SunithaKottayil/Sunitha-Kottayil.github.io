Learning Git

A practical guide to version control - no fancy stuff, just real learning
Hey there! Git might seem scary at first, but it's actually just a way to keep track of your code changes. Think of it like a super-powered "save" button that remembers everything you've ever done. This guide will walk you through the basics in plain English.

What is Git?

Okay, let's start simple. Git is basically a time machine for your code. Remember when you used to save files as "project_v1", "project_v2", "project_final", "project_final_really"? Git does that automatically, but way better.

Why Git is Awesome

The Old Way

• Files everywhere with weird names
• "final_final_really_final.html"
• Can't work with others easily
• Accidentally delete something important
• No idea what changed when

With Git

• Everything organized automatically
• Can go back to any point in time
• Work with friends without chaos
• Never lose your work again
• See exactly what you changed

The Main Ideas

Repository

Just a fancy word for your project folder. Git watches everything in here and remembers all your changes.

Commit

Like taking a photo of your code at a specific moment. "Hey Git, remember how my code looks right now!"

Branch

Think of it like a parallel universe. You can try new things without messing up your main code.

Merge

When you bring your experimental changes back into the main code. Like combining two recipes into one.

Remote

Your code stored online (like on GitHub) so you can work from anywhere and share with others.

Clone

Downloading a copy of someone else's project to your computer so you can work on it too.

Setting Up Git

Once you have Git installed, you need to tell it who you are. This is like signing up for a service - Git needs to know who's making the changes:

Terminal — -bash — 80×24
john@MacBook-Pro:~$ git config --global user.name "Your Full Name" john@MacBook-Pro:~$ git config --global user.email "your.email@example.com" john@MacBook-Pro:~$ git config --global init.defaultBranch main john@MacBook-Pro:~$ git config --global core.editor "code --wait"
Quick tip: The --global flag means these settings will apply to all your projects. If you want different settings for just one project, you can leave out the --global part.

Verification

Terminal — -bash — 80×24
john@MacBook-Pro:~$ git --version git version 2.39.0 john@MacBook-Pro:~$ git config --list --global user.name=Your Full Name user.email=your.email@example.com init.defaultbranch=main

The Commands You'll Use Most

git status
See what files you've changed and what Git is tracking. Your go-to command to check what's happening.
git add <file>
Tell Git "I want to save these changes." Use git add . to add everything.
git commit -m "message"
Actually save your changes with a note about what you did. Like a save point in a game.
git log
See all your previous saves. Use --oneline to see a shorter version.
git diff
See exactly what you changed in your files. Great for double-checking before committing.
git restore <file>
Oops! Undo changes to a file. Use --staged to unstage something you just added.

Let's See It in Action

Terminal
user@macbook:~/my-project$ echo "# My Project" > README.md user@macbook:~/my-project$ git status On branch main Untracked files: (use "git add <file>..." to include in what will be committed) README.md user@macbook:~/my-project$ git add README.md user@macbook:~/my-project$ git status On branch main Changes to be committed: (use "git restore --staged <file>..." to unstage) new file: README.md user@macbook:~/my-project$ git commit -m "Add project README" [main (root-commit) a1b2c3d] Add project README 1 file changed, 1 insertion(+) create mode 100644 README.md

Branches - Working on Different Things

Branches are like having multiple versions of your project. You can work on a new feature without messing up your main code. Think of it like having a rough draft and a final copy.

How Branches Work
●─────●─────●─────●─────● main │ │ │ ●─────● feature/login │ │ ●─────● feature/dashboard

Working with Branches

Branch Operations
$ git branch # List all branches * main feature/login $ git branch feature/dashboard # Create new branch $ git checkout feature/dashboard # Switch to branch $ git switch feature/dashboard # Modern alternative $ git checkout -b feature/new # Create and switch $ git switch -c feature/new # Modern alternative $ git branch -d feature/old # Delete branch $ git branch -D feature/old # Force delete

Combining Your Work

Fast-Forward Merge

When your main branch hasn't changed since you started your feature. Git just moves forward - clean and simple.

Three-Way Merge

When both branches have changed. Git creates a new "merge commit" that combines everything together.

Squash Merge

Takes all your feature commits and squishes them into one big commit. Makes history cleaner.

Rebase

Replays your changes on top of the latest main branch. Like rewriting history to make it look linear.

Merge Operations
$ git checkout main $ git merge feature/dashboard Updating a1b2c3d..e4f5g6h Fast-forward dashboard.html | 50 ++++++++++++++++++++++++++++++++++++++++++++++++++ styles.css | 23 +++++++++++++++++++++++ 2 files changed, 73 insertions(+) $ git merge --no-ff feature/login # Force merge commit $ git merge --squash feature/auth # Squash all commits

When Things Go Wrong - Conflicts

Conflict Resolution
$ git merge feature/conflicting-branch Auto-merging index.html CONFLICT (content): Merge conflict in index.html Automatic merge failed; fix conflicts and then commit the result. $ git status On branch main You have unmerged paths. (fix conflicts and run "git commit") Unmerged paths: both modified: index.html $ # Edit file to resolve conflicts, then: $ git add index.html $ git commit -m "Resolve merge conflict in index.html"
Don't panic! When Git finds conflicts, it puts special markers in your files (<<<<<<<, =======, >>>>>>>). Just edit the file, remove these markers, and pick which version you want to keep.

Working with Others

Remote repositories are like having your project stored online (like on GitHub). This lets you work from anywhere and share your code with other people.

Connecting to Online Repositories

Remote Repository Setup
$ git remote add origin https://github.com/username/repo.git $ git remote -v origin https://github.com/username/repo.git (fetch) origin https://github.com/username/repo.git (push) $ git remote rename origin upstream $ git remote remove upstream $ git remote set-url origin git@github.com:username/repo.git

Sharing Your Work

git push origin main
Upload your saved changes to GitHub so others can see them.
git pull origin main
Download the latest changes from GitHub and add them to your local copy.
git fetch origin
Check what's new on GitHub without actually downloading it yet.
git push -u origin feature
Upload your feature branch and tell Git to remember this connection.

Working with a Team

Different Ways to Work Together

Centralized Workflow

Everyone works on the same branch. Simple but can get messy when lots of people work on the same project.

Feature Branch Workflow

Each person works on their own branch for new features, then asks to merge it back when done.

Git Flow

A more organized way with special branches for features, releases, and quick fixes. Good for bigger projects.

GitHub Flow

A simpler version that's popular on GitHub. Make a branch, work on it, then merge it back quickly.

How Pull Requests Work

Feature Development Workflow
$ git checkout main $ git pull origin main $ git checkout -b feature/user-authentication $ # Make changes and commit $ git add . $ git commit -m "Implement user authentication system" $ git push -u origin feature/user-authentication $ # Create pull request on GitHub/GitLab $ # After review and approval, merge via web interface

Keeping Your Work Up to Date

Branch Synchronization
$ git checkout feature/my-feature $ git fetch origin $ git rebase origin/main $ # Alternative: merge instead of rebase $ git merge origin/main $ # Force push after rebase (use carefully) $ git push --force-with-lease origin feature/my-feature

Some Tips to Make Life Easier

Good Habits to Develop

Write Clear Commit Messages

Tell people what you did and why. "Fix login bug" is better than "stuff".

Commit Often

Save your work frequently with small, logical changes. Don't wait until everything is perfect.

Use Branches

Create separate branches for new features so you don't mess up your main code.

Review Before Committing

Always check what you're about to save with git status and git diff.

🚫 Use .gitignore

Tell Git to ignore temporary files and things that shouldn't be shared with others.

📤 Pull Before Push

Get the latest changes from others before you share your work to avoid conflicts.

Writing Good Commit Messages

Good vs Bad Commit Messages
# Good examples: git commit -m "Add user authentication middleware" git commit -m "Fix memory leak in image processing module" git commit -m "Update README with installation instructions" # Bad examples (avoid): git commit -m "fix bug" git commit -m "changes" git commit -m "stuff"

Some Cool Advanced Stuff

git stash
Temporarily hide your changes so you can switch branches without committing.
git cherry-pick <commit>
Take one specific change from another branch and add it to your current branch.
git rebase -i HEAD~3
Edit, combine, or reorder your last few commits. Like rewriting history!
git bisect
Find exactly when a bug was introduced by testing different versions.
git blame <file>
See who wrote each line of code and when. Great for figuring out who to ask about something.
git reflog
See everything you've done, even if you accidentally deleted something. Your safety net!

When Things Go Wrong

Problem Solution Command Note
Accidentally committed wrong files Undo last commit, keep changes git reset --soft HEAD~1 Files remain staged
Want to discard all local changes Reset to last commit git reset --hard HEAD Permanently loses changes
Wrong commit message Edit last commit message git commit --amend -m "New message" Only for unpushed commits
Need to ignore tracked file Remove from tracking git rm --cached filename Add to .gitignore after
Be careful! Some commands can delete your work permanently. Always make sure you have a backup before using git reset --hard or git push --force. When in doubt, use --force-with-lease instead of --force.

Shortcuts to Save Time

Setting Up Shortcuts
$ git config --global alias.st status $ git config --global alias.co checkout $ git config --global alias.br branch $ git config --global alias.cm commit $ git config --global alias.lg "log --oneline --graph --decorate" $ git config --global alias.unstage "reset HEAD --" $ git config --global alias.last "log -1 HEAD" $ # Now you can use shortcuts: $ git st # instead of git status $ git co main # instead of git checkout main $ git lg # beautiful log output
