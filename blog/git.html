Git Fundamentals

Git is a distributed version control system that tracks changes in source code during software development. It enables multiple developers to work on the same project efficiently while maintaining a complete history of all changes.

Version Control Comparison

❌ Without Version Control

• Files scattered across folders
• Manual backup naming
• Difficult collaboration
• Risk of losing work
• No change tracking

✅ With Git Version Control

• Complete change history
• Systematic organization
• Seamless collaboration
• Backup and recovery
• Parallel development

Core Git Concepts

📁 Repository

A directory containing your project files and the complete version history managed by Git.

📸 Commit

A snapshot of your project at a specific point in time, including all tracked changes.

🌳 Branch

An independent line of development that allows you to work on features without affecting the main code.

🔄 Merge

The process of combining changes from different branches into a single branch.

🌐 Remote

A version of your repository hosted on a server (like GitHub) for backup and collaboration.

👤 Clone

Creating a local copy of a remote repository on your computer for development.

Initial Configuration

Configure Git with your identity information for commit attribution:

Terminal — -bash — 80×24
john@MacBook-Pro:~$ git config --global user.name "Your Full Name" john@MacBook-Pro:~$ git config --global user.email "your.email@example.com" john@MacBook-Pro:~$ git config --global init.defaultBranch main john@MacBook-Pro:~$ git config --global core.editor "code --wait"
Configuration Scope: The --global flag applies settings to all repositories. Use --local for repository-specific settings or omit the flag for the current repository only.

Essential Commands

git status
Display the working tree status, showing modified, staged, and untracked files.
git add <file>
Add specific files to the staging area. Use git add . for all files.
git commit -m "message"
Create a commit with staged changes and a descriptive message.
git log
View commit history. Use --oneline for compact format.
git diff
Show changes between working directory and staging area.
git restore <file>
Discard changes in working directory. Use --staged to unstage.

Practical Example

Terminal
user@macbook:~/my-project$ echo "# My Project" > README.md user@macbook:~/my-project$ git status On branch main Untracked files: (use "git add <file>..." to include in what will be committed) README.md user@macbook:~/my-project$ git add README.md user@macbook:~/my-project$ git status On branch main Changes to be committed: (use "git restore --staged <file>..." to unstage) new file: README.md user@macbook:~/my-project$ git commit -m "Add project README" [main (root-commit) a1b2c3d] Add project README 1 file changed, 1 insertion(+) create mode 100644 README.md

Branching & Merging

Branches allow you to diverge from the main line of development and work on features independently without affecting the stable codebase.

Git Branching Model
●─────●─────●─────●─────● main │ │ │ ●─────● feature/login │ │ ●─────● feature/dashboard

Branch Management Commands

Branch Operations
$ git branch # List all branches * main feature/login $ git branch feature/dashboard # Create new branch $ git checkout feature/dashboard # Switch to branch $ git switch feature/dashboard # Modern alternative $ git checkout -b feature/new # Create and switch $ git switch -c feature/new # Modern alternative $ git branch -d feature/old # Delete branch $ git branch -D feature/old # Force delete

Merging Strategies

🔄 Fast-Forward Merge

When the target branch hasn't diverged, Git simply moves the pointer forward. Clean and linear history.

🔀 Three-Way Merge

Creates a new merge commit when branches have diverged. Preserves branch history.

📝 Squash Merge

Combines all commits from a feature branch into a single commit on the target branch.

🔄 Rebase

Replays commits from one branch onto another, creating a linear history without merge commits.

Merge Operations
$ git checkout main $ git merge feature/dashboard Updating a1b2c3d..e4f5g6h Fast-forward dashboard.html | 50 ++++++++++++++++++++++++++++++++++++++++++++++++++ styles.css | 23 +++++++++++++++++++++++ 2 files changed, 73 insertions(+) $ git merge --no-ff feature/login # Force merge commit $ git merge --squash feature/auth # Squash all commits

Resolving Merge Conflicts

Conflict Resolution
$ git merge feature/conflicting-branch Auto-merging index.html CONFLICT (content): Merge conflict in index.html Automatic merge failed; fix conflicts and then commit the result. $ git status On branch main You have unmerged paths. (fix conflicts and run "git commit") Unmerged paths: both modified: index.html $ # Edit file to resolve conflicts, then: $ git add index.html $ git commit -m "Resolve merge conflict in index.html"
Conflict Markers: Git marks conflicts in files with <<<<<<<, =======, and >>>>>>>. Remove these markers and choose the correct content before committing.

Remote Repositories

Remote repositories enable collaboration and backup by storing your project on external servers like GitHub, GitLab, or Bitbucket.

Remote Management

Remote Repository Setup
$ git remote add origin https://github.com/username/repo.git $ git remote -v origin https://github.com/username/repo.git (fetch) origin https://github.com/username/repo.git (push) $ git remote rename origin upstream $ git remote remove upstream $ git remote set-url origin git@github.com:username/repo.git

Synchronization Commands

git push origin main
Upload local commits to the remote repository's main branch.
git pull origin main
Download and merge changes from remote repository.
git fetch origin
Download changes without merging them into current branch.
git push -u origin feature
Push and set upstream tracking for the branch.

Team Collaboration

Common Workflows

🔄 Centralized Workflow

Everyone works on the main branch. Simple but can cause conflicts with larger teams.

🌊 Feature Branch Workflow

Each feature is developed in a separate branch and merged via pull requests.

🔀 Git Flow

Structured workflow with specific branches for features, releases, and hotfixes.

🚀 GitHub Flow

Simplified workflow with feature branches and continuous deployment from main.

Pull Request Process

Feature Development Workflow
$ git checkout main $ git pull origin main $ git checkout -b feature/user-authentication $ # Make changes and commit $ git add . $ git commit -m "Implement user authentication system" $ git push -u origin feature/user-authentication $ # Create pull request on GitHub/GitLab $ # After review and approval, merge via web interface

Keeping Branches Updated

Branch Synchronization
$ git checkout feature/my-feature $ git fetch origin $ git rebase origin/main $ # Alternative: merge instead of rebase $ git merge origin/main $ # Force push after rebase (use carefully) $ git push --force-with-lease origin feature/my-feature

Best Practices

Git Best Practices

📝 Write Clear Commit Messages

Use imperative mood, keep first line under 50 characters, explain what and why, not how.

🔄 Commit Often

Make small, logical commits that represent single changes or features.

🌳 Use Branches

Create branches for features, bug fixes, and experiments to keep main stable.

📋 Review Before Committing

Use git diff and git status to review changes before staging and committing.

🚫 Use .gitignore

Exclude temporary files, build artifacts, and sensitive information from version control.

📤 Pull Before Push

Always pull latest changes before pushing to avoid conflicts.

Commit Message Format

Good Commit Messages
# Good examples: git commit -m "Add user authentication middleware" git commit -m "Fix memory leak in image processing module" git commit -m "Update README with installation instructions" # Bad examples (avoid): git commit -m "fix bug" git commit -m "changes" git commit -m "stuff"

Advanced Git Techniques

git stash
Temporarily store uncommitted changes to switch branches quickly.
git cherry-pick <commit>
Apply a specific commit from another branch to current branch.
git rebase -i HEAD~3
Interactive rebase to edit, squash, or reorder the last 3 commits.
git bisect
Binary search through commit history to find when a bug was introduced.
git blame <file>
Show who last modified each line of a file and when.
git reflog
Show reference log of all commits, including "lost" ones.

Troubleshooting Common Issues

Problem Solution Command Note
Accidentally committed wrong files Undo last commit, keep changes git reset --soft HEAD~1 Files remain staged
Want to discard all local changes Reset to last commit git reset --hard HEAD ⚠️ Permanently loses changes
Wrong commit message Edit last commit message git commit --amend -m "New message" Only for unpushed commits
Need to ignore tracked file Remove from tracking git rm --cached filename Add to .gitignore after
Safety First: Always create backups before using destructive commands like git reset --hard or git push --force. Use --force-with-lease instead of --force when possible.

Git Aliases for Productivity

Useful Git Aliases
$ git config --global alias.st status $ git config --global alias.co checkout $ git config --global alias.br branch $ git config --global alias.cm commit $ git config --global alias.lg "log --oneline --graph --decorate" $ git config --global alias.unstage "reset HEAD --" $ git config --global alias.last "log -1 HEAD" $ # Now you can use shortcuts: $ git st # instead of git status $ git co main # instead of git checkout main $ git lg # beautiful log output
