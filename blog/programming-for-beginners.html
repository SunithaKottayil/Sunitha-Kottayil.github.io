01 — Foundation

What is programming?

Programming is the act of translating human intent into precise, unambiguous instructions a computer can execute. It is as much about thinking as it is about typing.

Analogy

Think of a recipe. A recipe is a set of steps that, if followed exactly, produces the same dish every time regardless of who cooks it. A program is exactly that — except the "cook" is a machine that follows instructions with perfect literalness, at enormous speed.

01a

Problem solving

Programming begins with a problem worth solving. The craft lies in translating a fuzzy human need into something precise enough for a machine to execute.

01b

Decomposition

Large problems become approachable when broken into small, independent pieces. This is one of the most valuable mental habits programming builds.

01c

Precision

Computers do exactly what they are told — not what you meant. Imprecision is the root cause of almost every bug you will ever encounter.

02 — Hardware

How computers think

Computers do not think. They switch. Understanding this distinction removes the mystery from programming and explains why precision matters so much.

Analogy

A computer's core operation is identical to a light switch: on or off, 1 or 0. Stack billions of those switches, cycle them billions of times per second, and complex behaviour emerges — not from intelligence, but from sheer speed and scale.

02a

Binary

Every number, letter, image, and sound your computer handles is ultimately a sequence of 1s and 0s. All other representations are conventions built on top.

02b

Speed

A modern processor executes several billion operations per second. Computers are not clever — they are fast, and speed at scale produces the appearance of intelligence.

02c

Memory

Computers store data in a hierarchy: registers (fastest, tiny), RAM (fast, temporary), storage (slow, permanent). Understanding this matters for writing efficient programs.

03 — Logic

Algorithms

An algorithm is a finite sequence of unambiguous steps that transforms an input into an output. You already use dozens of them every day.

Everyday example — making coffee

Fill kettle → boil water → add grounds → pour → wait → serve. Each step is discrete, ordered, and unambiguous. That structure is an algorithm. The same logic applies to sorting a list, routing a packet, or recommending a video.

Input

What goes in

Every algorithm starts with inputs — data it will process. Defining inputs precisely is often the hardest part of writing a good algorithm.

Process

The steps

The ordered sequence of operations that transforms the inputs. Each step must be finite and executable without ambiguity.

Output

What comes out

A correct algorithm always produces a predictable output for the same input. Consistency and correctness are the two measures of a good algorithm.

04 — Languages

Programming languages

A programming language is a formal notation for expressing algorithms in a way a computer can execute. Each language makes different trade-offs between readability, performance, and scope.

Analogy

Human languages differ in grammar, vocabulary, and idiom — but they can express the same ideas. Programming languages are similar: the same algorithm can be written in Python, Java, or C++. The choice of language shapes how you express the idea, not what idea you can express.

05 — Concepts

Core concepts

Four building blocks appear in virtually every program ever written. Master these and the rest of programming starts to feel like variations on a theme.

01 — Variables

Named storage

A variable is a name bound to a value. It lets you store, retrieve, and update data. Click to see an example.

02 — Functions

Reusable logic

A function is a named block of code you can call repeatedly. The alternative is copying the same logic everywhere.

03 — Loops

Repetition

Loops execute a block of code multiple times without you writing it multiple times. Essential for working with collections.

04 — Conditions

Decision making

Conditions let a program take different paths based on data. Without them, every program would do the same thing every time.

06 — Data

Types of data

Every piece of information your program handles has a type. Types determine what operations you can perform and how the data is stored.

Integer

Whole numbers

Used for counting: 0, 1, -3, 1000. No decimal point. Common for indices, ages, counts of things.

Float

Decimal numbers

Numbers with fractional parts: 3.14, -0.5, 2.718. Used for measurements, prices, scientific values.

String

Text

Any sequence of characters: "hello", "42", "user@email.com". Always quoted. The number "42" and the integer 42 are different things.

Boolean

True or false

Exactly two possible values. The result of any comparison is a boolean. Essential for conditions and control flow.

List / Array

Ordered collection

Multiple values grouped together: [1, 2, 3] or ["alice", "bob"]. Lets you work with many items using a single variable.

Dictionary

Key-value pairs

Labelled data: {"name": "Alice", "age": 30}. Used when you need to look things up by name rather than position.

07 — Method

The problem-solving approach

Writing code is the last step, not the first. Experienced programmers spend most of their time thinking, not typing.

Step 01

Understand

Can you explain the problem to someone else? If not, you do not understand it well enough to solve it. Restate it in your own words first.

Step 02

Decompose

Break the problem into the smallest possible sub-problems. Solve each independently. Combine the solutions.

Step 03

Plan in plain English

Write out your approach as numbered steps before touching a keyboard. If the steps are unclear in English, they will be wrong in code.

Step 04

Code the simplest version

Make it work before making it fast or elegant. A slow correct solution beats a fast incorrect one every time.

Step 05

Test with real data

Try expected inputs. Then try edge cases: empty lists, negative numbers, very large values. Bugs hide in corners.

Step 06

Debug systematically

When something fails, isolate where it fails. Change one thing at a time. Read the error message — it is trying to help you.

08 — Pitfalls

Common beginner mistakes

Every programmer makes these mistakes. Knowing them in advance does not mean you will avoid them — but it means you will recognise them faster when they happen.

Mistake 01

Coding before thinking

Jumping straight to the editor without a plan. The result is code that solves a slightly different problem than the one you meant to solve.

Mistake 02

Ignoring error messages

Error messages tell you exactly what went wrong and often where. Most beginners panic and ignore them. Read every word before changing anything.

Mistake 03

Over-engineering early

Building a complex solution before the simple one works. Start with the most naive approach that could possibly be correct, then improve it.

Mistake 04

Insufficient testing

Testing only the happy path. Real software fails on edge cases: empty inputs, unexpected characters, values at the boundary of valid ranges.

Mistake 05

Comparing your progress

Measuring yourself against others at a different stage of their journey. The only meaningful comparison is yourself six months ago.

Mistake 06

Giving up at friction

Confusion is not a signal to stop — it is a signal that learning is happening. The discomfort you feel is the sensation of your mental model changing.

09 — Roadmap

Your learning journey

What to expect in the weeks and months ahead. Progress is rarely linear, but there are common patterns in how people develop as programmers.

Weeks 1–2

The basics

Variables, printing, arithmetic, simple input. Everything is new. Write small programs just to see them run.

Weeks 3–4

First friction

Loops and conditions introduce complexity. You will hit your first "I don't understand" wall. This is expected. Slow down, not stop.

Weeks 5–8

Things click

Concepts that seemed independent start connecting. You build programs that do something genuinely useful. Confidence grows.

Weeks 9–12

Independent creation

You start building things without following tutorials step by step. You encounter new problems and figure them out without asking for help every time.
