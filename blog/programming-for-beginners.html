01 — Foundation

What is programming?

Programming is the act of expressing human intent as precise, unambiguous instructions a computer can execute — reliably, every time.

📋
Analogy

Think of a recipe. It is a set of steps that, followed exactly, produces the same dish every time regardless of who cooks it. A program is exactly that — except the "cook" is a machine that is perfectly literal, never improvises, and works at billions of steps per second.

01a

Problem solving

Programming begins with a problem worth solving. The craft lies in translating a fuzzy human need into something a machine can execute precisely.

01b

Decomposition

Large problems become manageable when broken into small, independent pieces. This mental habit is one of the most durable skills programming builds.

01c

Precision

Computers do exactly what they are told — not what you meant. Ambiguity is the root cause of nearly every bug you will ever encounter.

02 — Hardware

How computers think

Computers do not think. They switch. Understanding this distinction removes the mystery from programming and clarifies why precision matters so much.

💡
Analogy

A computer's core operation is identical to a light switch — on or off, 1 or 0. Stack billions of those switches, cycle them billions of times per second, and complex behaviour emerges — not from intelligence, but from sheer scale and speed.

Binary

On and off

Every number, letter, image, and sound is ultimately a sequence of 1s and 0s. Everything else is a convention built on top of that foundation.

Speed

Billions per second

A modern processor executes billions of simple operations per second. Computers are not clever — they are extraordinarily fast at following simple rules.

Memory

Perfect recall

Computers store data in a hierarchy: registers (fastest, tiny), RAM (fast, temporary), storage (slow, permanent). This hierarchy shapes how programs are written.

03 — Logic

Algorithms

An algorithm is a finite, ordered sequence of unambiguous steps that transforms an input into an output. You already use dozens of them every day without realising it.

☕
Everyday example

Fill kettle → boil water → add coffee → pour → wait → serve. Each step is discrete, ordered, and unambiguous. That structure is an algorithm. The same logic governs sorting a list, routing internet traffic, or ranking search results.

Input

What goes in

Every algorithm operates on inputs — data it will process. Defining inputs precisely is often the hardest part of writing a correct algorithm.

Process

The steps

An ordered sequence of operations that transform inputs into outputs. Each step must be finite and executable without ambiguity.

Output

What comes out

A correct algorithm produces the same output for the same input, every time. Predictability and correctness are the two measures of quality.

04 — Languages

Programming languages

A programming language is a formal notation for expressing algorithms in a form a computer can execute. Each language makes different trade-offs between readability, performance, and scope.

🌐
Analogy

Human languages differ in grammar and vocabulary, but they can express the same ideas. Programming languages work the same way — the same algorithm can be written in Python, Java, or C++. The language shapes how you express the idea, not what idea you can express.

Language Best for Why
PythonData, automation, learningReads like English; minimal noise
JavaScriptWeb interfacesRuns natively in every browser
JavaEnterprise, Android appsStrongly typed; runs anywhere
C++Games, systems, performanceDirect hardware access; very fast
SwiftiOS and macOSSafe by design; Apple's modern language
SQLDatabasesDeclarative — describe the result, not the steps

06 — Data

Types of data

Every value in a program has a type. Types determine what operations you can perform and how data is stored in memory.

Integer

Whole numbers

Used for counting: 0, 1, −3, 1000. No decimal point. Common for indices, ages, and any quantity that cannot be fractional.

Float

Decimal numbers

Numbers with fractional parts: 3.14, −0.5, 2.718. Used for measurements, prices, and scientific values.

String

Text

Any sequence of characters: "hello", "42", "user@email.com". Always quoted. The string "42" and the integer 42 are completely different things.

Boolean

True or false

Exactly two possible values. Any comparison returns a boolean. Essential for conditions and controlling program flow.

List

Ordered collection

Multiple values grouped together: [1, 2, 3] or ["alice", "bob"]. Lets you operate on many items through a single variable.

Dictionary

Key-value pairs

Labelled data: {"name": "Alice", "age": 30}. Used when you need to look things up by name rather than by position.

07 — Method

How programmers solve problems

Writing code is the last step, not the first. Experienced programmers spend more time thinking than typing, and their programs show it.

Step 01

Understand

Can you explain the problem to someone else, in plain language? If not, you do not understand it well enough to solve it.

Step 02

Decompose

Break the problem into the smallest possible sub-problems. Solve each one independently, then combine the solutions.

Step 03

Plan in plain English

Write your approach as numbered steps before touching the keyboard. If it is unclear in English, it will be wrong in code.

Step 04

Code the simplest version

Make it correct before making it fast or elegant. A slow, correct solution beats a fast, incorrect one in every situation.

Step 05

Test with real data

Try expected inputs, then edge cases: empty lists, negative numbers, very large values. Bugs live in corners.

Step 06

Debug systematically

When something fails, isolate where it fails. Change one thing at a time. Read the error message — it is trying to help you.

08 — Pitfalls

Common beginner mistakes

Every programmer makes these. Knowing them in advance does not mean you will avoid them — but you will recognise them faster, and recover quicker.

Mistake 01

Coding before thinking

Jumping straight to the editor without a plan. The result is code that solves a slightly different problem than the one you actually meant to solve.

Mistake 02

Ignoring error messages

Error messages tell you what went wrong and often where. Most beginners panic and ignore them. Read every word before changing anything.

Mistake 03

Over-engineering early

Building a complex solution before a simple one works. Start with the most naive approach that could be correct, then improve from there.

Mistake 04

Insufficient testing

Only testing the happy path. Real programs fail on edge cases: empty inputs, unexpected characters, values at the boundary of valid ranges.

Mistake 05

Comparing progress

Measuring yourself against people at a different stage of their journey. The only meaningful comparison is yourself six months ago.

Mistake 06

Quitting at friction

Confusion is not a signal to stop — it is a signal that learning is happening. The discomfort you feel is your mental model changing shape.

09 — Roadmap

Your learning journey

What to expect over the coming weeks. Progress is rarely linear, but there are patterns in how people develop as programmers.

Weeks 1–2

The basics

Variables, printing, arithmetic, basic input. Everything is new. Write small programs simply to see them run — the novelty is its own motivation.

Weeks 3–4

First friction

Loops and conditions introduce real complexity. You will hit your first "I do not understand" wall. This is expected. Slow down, do not stop.

Weeks 5–8

Things click

Concepts that seemed separate start connecting. You build programs that do something genuinely useful. Confidence grows noticeably.

Weeks 9–12

Independent creation

You start building things without following tutorials. You encounter new problems and figure them out without asking for help every time.
