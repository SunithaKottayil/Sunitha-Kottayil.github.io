What is TypeScript?

ANALOGY: Think of it Like This

Imagine JavaScript is like writing with a pencil - you can write anything, but sometimes you make mistakes that are hard to catch. TypeScript is like having a smart grammar checker that helps you write better, clearer code and catches mistakes before they become problems!

TypeScript is a programming language created by Microsoft that builds on JavaScript by adding static type definitions. Don't worry if that sounds complicated - we'll break it down!

Why Should You Care About TypeScript?

Think about popular apps you use daily:

  • Slack - Uses TypeScript to manage millions of messages
  • Discord - Keeps chat features reliable with TypeScript
  • Spotify - Manages your music library with type safety
  • Netflix - Ensures smooth video streaming

FACT: Fun Fact

According to the 2024 Stack Overflow Survey, 92% of JavaScript developers now use TypeScript! It's not just a trend - it's becoming the standard.

Understanding Types - The Heart of TypeScript

STORE: Types are Like Labels in a Store

Imagine you're organizing a store. You put labels on shelves: "Books," "Electronics," "Clothing." Types in TypeScript work the same way - they're labels that tell us what kind of data we're working with. This prevents confusion like accidentally putting a banana in the electronics section!

The Basic Types - Your Foundation

TypeScript has several basic types that cover most of what you'll need. Let's explore them with real examples!

1. String - For Text

Working with strings
// Strings hold text - like usernames, messages, or names let studentName: string = "Alex Johnson"; let favoriteQuote: string = "The only way to do great work is to love what you do"; let emailAddress: string = "alex@example.com"; // You can use single quotes, double quotes, or template literals let message: string = `Welcome back, ${studentName}!`; console.log(message); // "Welcome back, Alex Johnson!"

2. Number - For All Numeric Values

Working with numbers
// TypeScript uses one type for all numbers (integers, decimals, etc.) let age: number = 17; let gpa: number = 3.85; let temperature: number = -5.2; let phoneNumber: number = 5551234567; // Math operations work as expected let yearsUntilGraduation: number = 18 - age; console.log(`Years until graduation: ${yearsUntilGraduation}`);

3. Boolean - For True/False Values

Working with booleans
// Booleans represent yes/no, on/off, true/false let isStudent: boolean = true; let hasDriversLicense: boolean = false; let isWeekend: boolean = true; // Great for making decisions in your code if (isStudent && isWeekend) { console.log("Time to relax and maybe do some homework!"); }

4. Array - For Lists of Things

Working with arrays
// Arrays hold multiple values of the same type let favoriteColors: string[] = ["blue", "green", "purple"]; let testScores: number[] = [95, 87, 92, 88]; let daysOff: boolean[] = [false, false, false, false, false, true, true]; // Alternative syntax (both work the same way) let hobbies: Array = ["reading", "gaming", "coding", "music"]; // Access items by their position (starting from 0) console.log(`My favorite color is ${favoriteColors[0]}`); // "blue"

Interfaces - Creating Blueprints for Objects

ARCHITECTURE: Interfaces are Like Blueprints

Imagine you're designing a house. Before building, you create a blueprint that shows where the kitchen, bedrooms, and bathrooms should go. Interfaces work the same way - they're blueprints that define what properties an object should have!

Your First Interface

Let's start with something relatable - describing a student!

Creating a Student interface
// Interface: The blueprint for what a Student should look like interface Student { name: string; age: number; grade: number; email: string; isEnrolled: boolean; } // Using the interface to create actual student objects const student1: Student = { name: "Emma Thompson", age: 16, grade: 11, email: "emma.thompson@school.edu", isEnrolled: true }; const student2: Student = { name: "Marcus Rodriguez", age: 17, grade: 12, email: "marcus.r@school.edu", isEnrolled: true };

BENEFIT: Why Interfaces Rock

If you try to create a student without all the required properties, TypeScript will immediately tell you what's missing. It's like having a checklist that prevents you from forgetting important details!

Optional Properties - When Things Might Be Missing

Sometimes, not every property is required. Use the ? symbol to make properties optional.

Optional properties with ?
interface SocialMediaProfile { username: string; displayName: string; bio?: string; // Optional - not everyone has a bio profilePicture?: string; // Optional followerCount: number; isVerified?: boolean; // Optional - defaults to false } // This works even without the optional properties! const profile1: SocialMediaProfile = { username: "coding_teen", displayName: "Alex the Coder", followerCount: 1250 }; // This also works with optional properties included const profile2: SocialMediaProfile = { username: "music_lover_17", displayName: "Taylor Swift Fan", bio: "[MUSIC] Music is life! Senior at Valley High [GRADUATION]", followerCount: 523, isVerified: false };

Interfaces with Methods - Adding Behavior

Interfaces can also describe functions (methods) that an object should have.

Interfaces with methods
interface GameCharacter { name: string; level: number; health: number; // Methods the character should have attack(target: string): string; heal(amount: number): void; levelUp(): void; } // Creating a character that follows the interface const hero: GameCharacter = { name: "Aria the Brave", level: 5, health: 100, attack(target: string): string { return `${this.name} attacks ${target} for 25 damage!`; }, heal(amount: number): void { this.health += amount; console.log(`${this.name} heals for ${amount} HP. Health: ${this.health}`); }, levelUp(): void { this.level++; this.health += 20; console.log(`${this.name} reached level ${this.level}!`); } };

Classes - Building Objects with Behavior

FACTORY: Classes are Like Cookie Cutters

Think of a class as a cookie cutter and objects as the cookies. The cookie cutter (class) defines the shape and properties, but each cookie (object) you make can have different flavors, colors, or decorations while keeping the same basic structure!

Your First Class

Let's create a class to represent something familiar - a smartphone!

Creating a Smartphone class
class Smartphone { // Properties (characteristics of the phone) brand: string; model: string; batteryLevel: number; isOn: boolean; // Constructor - runs when creating a new phone constructor(brand: string, model: string) { this.brand = brand; this.model = model; this.batteryLevel = 100; // New phones start at 100% this.isOn = false; // Phones start turned off } // Methods (things the phone can do) turnOn(): void { this.isOn = true; console.log(`${this.brand} ${this.model} is now ON!`); } turnOff(): void { this.isOn = false; console.log(`${this.brand} ${this.model} is now OFF`); } useBattery(percentage: number): void { this.batteryLevel -= percentage; if (this.batteryLevel <= 0) { this.batteryLevel = 0; this.turnOff(); console.log("Battery dead! Phone shutting down..."); } } charge(percentage: number): void { this.batteryLevel += percentage; if (this.batteryLevel > 100) { this.batteryLevel = 100; } console.log(`Charging... Battery at ${this.batteryLevel}%`); } } // Creating instances (actual phone objects) const myPhone = new Smartphone("Apple", "iPhone 15"); const friendPhone = new Smartphone("Samsung", "Galaxy S24"); // Using the phones myPhone.turnOn(); // Apple iPhone 15 is now ON! myPhone.useBattery(25); // Battery goes to 75% myPhone.charge(15); // Battery goes to 90%

Inheritance - Classes Learning from Other Classes

INHERITANCE: Like Family Traits

Just like you might inherit your parent's eye color or height, classes can inherit properties and methods from parent classes. A "Student" class might inherit basic "Person" properties and add school-specific features!

Class inheritance
// Base class - what all vehicles have in common class Vehicle { protected brand: string; protected year: number; protected color: string; constructor(brand: string, year: number, color: string) { this.brand = brand; this.year = year; this.color = color; } public getInfo(): string { return `${this.year} ${this.color} ${this.brand}`; } public start(): void { console.log(`${this.getInfo()} is starting...`); } } // Car class extends Vehicle - inherits all Vehicle properties and methods class Car extends Vehicle { private numberOfDoors: number; private fuelLevel: number; constructor(brand: string, year: number, color: string, doors: number) { super(brand, year, color); // Call parent constructor this.numberOfDoors = doors; this.fuelLevel = 100; } // New method specific to cars public honk(): void { console.log(`${this.getInfo()} says BEEP BEEP!`); } // Override parent method with car-specific behavior public start(): void { if (this.fuelLevel > 0) { console.log(`Starting ${this.getInfo()}... Engine running!`); } else { console.log(`${this.getInfo()} needs fuel to start!`); } } public drive(distance: number): void { const fuelUsed = distance / 10; // 10 miles per fuel unit if (this.fuelLevel >= fuelUsed) { this.fuelLevel -= fuelUsed; console.log(`Drove ${distance} miles. Fuel remaining: ${this.fuelLevel.toFixed(1)}`); } else { console.log("Not enough fuel for this trip!"); } } } // Using our classes const myCar = new Car("Toyota", 2023, "Blue", 4); myCar.start(); // Car-specific start myCar.honk(); // Car-specific method myCar.drive(50); // Car-specific method

Modules - Organizing Your Code Like a Pro

ORGANIZATION: Modules are Like School Subjects

Imagine if all your school subjects were taught in one giant room with no organization - math, science, English, history all mixed together! That would be chaos. Modules help organize your code like separate classrooms, each with a specific purpose and clear boundaries.

Why Do We Need Modules?

As your projects grow, putting everything in one file becomes a nightmare. Modules help you:

  • ORGANIZE: Keep related functions together
  • ENCAPSULATE: Hide internal details
  • REUSE: Use code in multiple places
  • COLLABORATE: Team members can work on different modules
  • DEBUG: Easier to find and fix issues

Creating Your First Module

Let's build a simple math utilities module!

mathUtils.ts - Your first module
// mathUtils.ts - A module for math operations // Export individual functions export function add(a: number, b: number): number { return a + b; } export function subtract(a: number, b: number): number { return a - b; } export function multiply(a: number, b: number): number { return a * b; } export function divide(a: number, b: number): number { if (b === 0) { throw new Error("Cannot divide by zero!"); } return a / b; } // Export a constant export const PI = 3.14159; // Export a class export class Calculator { private history: string[] = []; add(a: number, b: number): number { const result = a + b; this.history.push(`${a} + ${b} = ${result}`); return result; } getHistory(): string[] { return [...this.history]; // Return a copy } clearHistory(): void { this.history = []; } }

Using Your Module

Now let's use our math utilities in another file!

main.ts - Using our module
// Import specific functions from our module import { add, multiply, PI, Calculator } from './mathUtils'; // Using imported functions console.log("Addition:", add(5, 3)); // 8 console.log("Multiplication:", multiply(4, 7)); // 28 console.log("PI value:", PI); // 3.14159 // Using the imported class const calc = new Calculator(); calc.add(10, 5); calc.add(20, 8); console.log("Calculator history:", calc.getHistory());

Default Exports - The Star of the Show

🌟 Like the Main Character

Sometimes a module has one main thing it does - like a movie's main character. Default exports let you highlight that "main character" of your module!

gameCharacter.ts - Using default export
// Default export - the main thing this module provides export default class GameCharacter { private name: string; private level: number; private health: number; private experience: number; constructor(name: string) { this.name = name; this.level = 1; this.health = 100; this.experience = 0; } public getName(): string { return this.name; } public getLevel(): number { return this.level; } public gainExperience(points: number): void { this.experience += points; console.log(`${this.name} gained ${points} XP!`); // Level up every 100 XP if (this.experience >= this.level * 100) { this.levelUp(); } } private levelUp(): void { this.level++; this.health += 20; this.experience = 0; console.log(`${this.name} leveled up! Now level ${this.level}`); } public getStats(): string { return `${this.name} - Level: ${this.level}, Health: ${this.health}, XP: ${this.experience}`; } } // You can still have named exports alongside default export export const MAX_LEVEL = 50; export const STARTING_HEALTH = 100;
game.ts - Using default and named imports
// Import the default export (can name it whatever you want) import GameCharacter from './gameCharacter'; // Import named exports alongside default import GameCharacter, { MAX_LEVEL, STARTING_HEALTH } from './gameCharacter'; // Create characters const player = new GameCharacter("Hero"); console.log("Player:", player.getStats()); // Level up the player player.gainExperience(250); console.log("After training:", player.getStats()); console.log("Max level in this game:", MAX_LEVEL);

Generics - Writing Flexible, Reusable Code

FLEXIBILITY: Generics are Like Adjustable Tools

Think of an adjustable wrench - it can fit different sized bolts without needing a separate tool for each size. Generics let you write code that works with different types without writing separate functions for each type!

The Problem Generics Solve

Imagine you need functions to work with different types of data:

Without generics (repetitive)
// Need separate functions for each type function getFirstString(items: string[]): string { return items[0]; } function getFirstNumber(items: number[]): number { return items[0]; } function getFirstBoolean(items: boolean[]): boolean { return items[0]; } // This gets tedious and hard to maintain!
With generics (one solution)
// One function that works with any type! function getFirst(items: T[]): T { return items[0]; } // Works with any type const firstString = getFirst(["a", "b", "c"]); // string const firstNumber = getFirst([1, 2, 3]); // number const firstBoolean = getFirst([true, false]); // boolean

Your First Generic Function

Let's start with a simple example - a function that creates a box to store any type of item:

Basic generic function
// T is a "type parameter" - a placeholder for any type function createBox(item: T): { content: T; isEmpty: boolean } { return { content: item, isEmpty: false }; } // TypeScript automatically figures out the type! const stringBox = createBox("Hello!"); // T becomes string const numberBox = createBox(42); // T becomes number const booleanBox = createBox(true); // T becomes boolean // You can also be explicit about the type const explicitBox = createBox("Explicit type!"); console.log(stringBox.content); // "Hello!" (TypeScript knows it's a string) console.log(numberBox.content); // 42 (TypeScript knows it's a number)

Generic Classes - Containers for Any Type

STORAGE: Like Different Sized Storage Boxes

A storage company might have the same box design but in different sizes - small for books, medium for clothes, large for furniture. Generic classes work similarly - same structure, different content types!

Generic class example
class Stack { private items: T[] = []; // Add item to top of stack push(item: T): void { this.items.push(item); console.log(`Added ${item} to stack`); } // Remove and return top item pop(): T | undefined { const item = this.items.pop(); if (item !== undefined) { console.log(`Removed ${item} from stack`); } return item; } // Look at top item without removing it peek(): T | undefined { return this.items[this.items.length - 1]; } // Check if stack is empty isEmpty(): boolean { return this.items.length === 0; } // Get stack size size(): number { return this.items.length; } } // Create different types of stacks const numberStack = new Stack(); numberStack.push(1); numberStack.push(2); numberStack.push(3); console.log("Top number:", numberStack.peek()); // 3 const stringStack = new Stack(); stringStack.push("first"); stringStack.push("second"); stringStack.push("third"); console.log("Top string:", stringStack.peek()); // "third" // Even works with custom types! interface Task { id: number; description: string; completed: boolean; } const taskStack = new Stack(); taskStack.push({ id: 1, description: "Learn TypeScript", completed: false }); taskStack.push({ id: 2, description: "Build a project", completed: false }); console.log("Current tasks:", taskStack.size());

Generic Constraints - Setting Boundaries

🚧 Like Setting Rules for a Game

Sometimes you want generics to be flexible, but not TOO flexible. It's like saying "you can use any card game, but it must have standard playing cards" - you're setting a boundary while keeping flexibility!

Generic constraints
// Constraint: T must have a 'length' property function logLength(item: T): T { console.log(`Item has length: ${item.length}`); return item; } // These work because they have 'length' property logLength("Hello World"); // string has length logLength([1, 2, 3, 4, 5]); // array has length logLength({ name: "test", length: 10 }); // object with length property // This would NOT work: // logLength(123); // ❌ Error! number doesn't have length // Constraint: T must extend a base interface interface Identifiable { id: number; } function updateEntity(entity: T, updates: Partial): T { console.log(`Updating entity with ID: ${entity.id}`); return { ...entity, ...updates }; } // Works with any object that has an id const user = { id: 1, name: "Alice", email: "alice@example.com" }; const product = { id: 101, name: "Laptop", price: 999 }; const updatedUser = updateEntity(user, { name: "Alice Johnson" }); const updatedProduct = updateEntity(product, { price: 899 });

findAll(): T[]; create(data: Omit): T; update(id: string, updates: Partial): T | undefined; delete(id: string): boolean; findBy(key: K, value: T[K]): T[]; } // Generic Repository Implementation class InMemoryRepository implements Repository { private entities: Map = new Map(); findById(id: string): T | undefined { return this.entities.get(id); } findAll(): T[] { return Array.from(this.entities.values()); } create(data: Omit): T { const now = new Date(); const id = this.generateId(); const entity = { ...data, id, createdAt: now, updatedAt: now } as T; this.entities.set(id, entity); return entity; } update(id: string, updates: Partial): T | undefined { const entity = this.entities.get(id); if (!entity) return undefined; const updatedEntity = { ...entity, ...updates, updatedAt: new Date() } as T; this.entities.set(id, updatedEntity); return updatedEntity; } delete(id: string): boolean { return this.entities.delete(id);
