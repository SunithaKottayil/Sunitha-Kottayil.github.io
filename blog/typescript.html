When to Use Generics

Use generics when:

  • You need the same logic for different types
  • You want to maintain type safety
  • You're building reusable components/functions
  • You want to avoid code duplication

Don't use generics when:

  • You only work with one specific type
  • The logic is completely different for each type
  • It makes the code harder to understand

Generic Best Practices

  • Use descriptive names: T for Type, K for Key, V for Value
  • Add constraints when needed: Don't make generics too flexible
  • Provide default types: <T = string> for common cases
  • Document your generics: Explain what types are expected

Generics - Writing Flexible, Reusable Code

Generics are Like Adjustable Tools

Think of an adjustable wrench - it can fit different sized bolts without needing a separate tool for each size. Generics let you write code that works with different types without writing separate functions for each type!

The Problem Generics Solve

Imagine you need functions to work with different types of data:

Without Generics (Repetitive)

// Need separate functions for each type function getFirstString(items: string[]): string { return items[0]; } function getFirstNumber(items: number[]): number { return items[0]; } function getFirstBoolean(items: boolean[]): boolean { return items[0]; } // This gets tedious and hard to maintain!

✅ With Generics (One Solution)

// One function that works with any type! function getFirst(items: T[]): T { return items[0]; } // Works with any type const firstString = getFirst(["a", "b", "c"]); // string const firstNumber = getFirst([1, 2, 3]); // number const firstBoolean = getFirst([true, false]); // boolean

Understanding Types - The Heart of TypeScript 🏷

Types are Like Labels in a Store

Imagine you're organizing a store. You put labels on shelves: "Books," "Electronics," "Clothing." Types in TypeScript work the same way - they're labels that tell us what kind of data we're working with. This prevents confusion like accidentally putting a banana in the electronics section!

The Basic Types - Your Foundation

TypeScript has several basic types that cover most of what you'll need. Let's explore them with real examples!

1. String - For Text

Working with strings
// Strings hold text - like usernames, messages, or names let studentName: string = "Alex Johnson"; let favoriteQuote: string = "The only way to do great work is to love what you do"; let emailAddress: string = "alex@example.com"; // You can use single quotes, double quotes, or template literals let message: string = `Welcome back, ${studentName}!`; console.log(message); // "Welcome back, Alex Johnson!"

2. Number - For All Numeric Values

Working with numbers
// TypeScript uses one type for all numbers (integers, decimals, etc.) let age: number = 17; let gpa: number = 3.85; let temperature: number = -5.2; let phoneNumber: number = 5551234567; // Math operations work as expected let yearsUntilGraduation: number = 18 - age; console.log(`Years until graduation: ${yearsUntilGraduation}`);

3. Boolean - For True/False Values

Working with booleans
// Booleans represent yes/no, on/off, true/false let isStudent: boolean = true; let hasDriversLicense: boolean = false; let isWeekend: boolean = true; // Great for making decisions in your code if (isStudent && isWeekend) { console.log("Time to relax and maybe do some homework!"); }

4. Array - For Lists of Things

Working with arrays
// Arrays hold multiple values of the same type let favoriteColors: string[] = ["blue", "green", "purple"]; let testScores: number[] = [95, 87, 92, 88]; let daysOff: boolean[] = [false, false, false, false, false, true, true]; // Alternative syntax (both work the same way) let hobbies: Array = ["reading", "gaming", "coding", "music"]; // Access items by their position (starting from 0) console.log(`My favorite color is ${favoriteColors[0]}`); // "blue"

TypeScript is Like a Detective

Sometimes you don't need to tell TypeScript what type something is - it can figure it out! It's like when you see someone carrying a basketball - you can guess they're probably going to play basketball.

Union Types - When You Need Flexibility

Sometimes a variable might hold different types of data. Union types let you handle this safely!

Union types in action
// A user ID might be a number or a string let userId: number | string; userId = 12345; // Works! userId = "user_abc123"; // Also works! // Phone numbers could be numbers or strings let phoneNumber: number | string = "555-123-4567"; // Function that accepts multiple types function printId(id: number | string) { console.log(`Your ID is: ${id}`); } printId(123); // Works printId("abc"); // Also works

Interfaces - Creating Blueprints for Objects 📋

Interfaces are Like Architectural Blueprints

Imagine you're designing a house. Before building, you create a blueprint that shows where the kitchen, bedrooms, and bathrooms should go. Interfaces work the same way - they're blueprints that define what properties an object should have!

Your First Interface

Let's start with something relatable - describing a student!

Creating a Student interface
// Interface: The blueprint for what a Student should look like interface Student { name: string; age: number; grade: number; email: string; isEnrolled: boolean; } // Using the interface to create actual student objects const student1: Student = { name: "Emma Thompson", age: 16, grade: 11, email: "emma.thompson@school.edu", isEnrolled: true }; const student2: Student = { name: "Marcus Rodriguez", age: 17, grade: 12, email: "marcus.r@school.edu", isEnrolled: true };

If you try to create a student without all the required properties, TypeScript will immediately tell you what's missing. It's like having a checklist that prevents you from forgetting important details!

Optional Properties - When Things Might Be Missing

Sometimes, not every property is required. Use the ? symbol to make properties optional.

Optional properties with ?

Senior at Valley High 🎓", followerCount: 523, isVerified: false };

Readonly Properties - Values That Never Change

Some properties should never be changed after they're set, like a student ID number.

Readonly properties
interface Student { readonly studentId: number; // Can't be changed after creation readonly schoolEmail: string; // School assigns this name: string; // Can be changed (if someone changes their name) grade: number; // Can be updated each year } const student: Student = { studentId: 2024001, schoolEmail: "s2024001@valleyhigh.edu", name: "Jordan Smith", grade: 10 }; // This is allowed student.name = "Jordan Smith-Johnson"; // Name change is okay student.grade = 11; // Grade update is fine // This would cause an error! // student.studentId = 2024002; // Error! readonly property

Interfaces with Methods - Adding Behavior

Interfaces can also describe functions (methods) that an object should have.

Interfaces with methods

Health: ${this.health}`); }, levelUp(): void { this.level++; this.health += 20; console.log(` ${this.name} reached level ${this.level}!`); } };

Like Inheriting Traits from Parents

Classes - Building Objects with Behavior

Classes are Like Cookie Cutters

Think of a class as a cookie cutter and objects as the cookies. The cookie cutter (class) defines the shape and properties, but each cookie (object) you make can have different flavors, colors, or decorations while keeping the same basic structure!

Your First Class

Let's create a class to represent something familiar - a smartphone!

Creating a Smartphone class
class Smartphone { // Properties (characteristics of the phone) brand: string; model: string; batteryLevel: number; isOn: boolean; // Constructor - runs when creating a new phone constructor(brand: string, model: string) { this.brand = brand; this.model = model; this.batteryLevel = 100; // New phones start at 100% this.isOn = false; // Phones start turned off } // Methods (things the phone can do) turnOn(): void { this.isOn = true; console.log(`${this.brand} ${this.model} is now ON! `); } turnOff(): void { this.isOn = false; console.log(`${this.brand} ${this.model} is now OFF `); } useBattery(percentage: number): void { this.batteryLevel -= percentage; if (this.batteryLevel <= 0) { this.batteryLevel = 0; this.turnOff(); console.log(" Battery dead! Phone shutting down..."); } } charge(percentage: number): void { this.batteryLevel += percentage; if (this.batteryLevel > 100) { this.batteryLevel = 100; } console.log(` Charging... Battery at ${this.batteryLevel}%`); } } // Creating instances (actual phone objects) const myPhone = new Smartphone("Apple", "iPhone 15"); const friendPhone = new Smartphone("Samsung", "Galaxy S24"); // Using the phones myPhone.turnOn(); // Apple iPhone 15 is now ON! myPhone.useBattery(25); // Battery goes to 75% myPhone.charge(15); // Battery goes to 90%

Access Modifiers - Controlling What's Visible

Like Rooms in Your House

Your bedroom is private (only you can enter), the living room is public (anyone can visit), and maybe the home office is protected (only family members can use it). Classes work similarly with access modifiers!

Access modifiers in action
class BankAccount { public accountHolder: string; // Anyone can see this private balance: number; // Only this class can access protected accountNumber: string; // This class and subclasses constructor(holder: string, initialBalance: number) { this.accountHolder = holder; this.balance = initialBalance; this.accountNumber = this.generateAccountNumber(); } // Public method - anyone can use public deposit(amount: number): void { if (amount > 0) { this.balance += amount; console.log(` Deposited ${amount}. New balance: ${this.balance}`); } } // Public method - anyone can use public withdraw(amount: number): boolean { if (this.canWithdraw(amount)) { this.balance -= amount; console.log(`💸 Withdrew ${amount}. New balance: ${this.balance}`); return true; } console.log(" Insufficient funds!"); return false; } // Public method to safely check balance public getBalance(): number { return this.balance; } // Private method - only this class can use private canWithdraw(amount: number): boolean { return amount > 0 && amount <= this.balance; } // Private method - only this class can use private generateAccountNumber(): string { return Math.random().toString(36).substr(2, 9).toUpperCase(); } } const myAccount = new BankAccount("Alex Johnson", 1000); // These work (public methods) myAccount.deposit(500); console.log(`Account holder: ${myAccount.accountHolder}`); console.log(`Current balance: ${myAccount.getBalance()}`); // These would cause errors (private/protected access) // console.log(myAccount.balance); // Error! Private // console.log(myAccount.accountNumber); // Error! Protected

Inheritance - Classes Learning from Other Classes

Like Family Traits

Just like you might inherit your parent's eye color or height, classes can inherit properties and methods from parent classes. A "Student" class might inherit basic "Person" properties and add school-specific features!

Class inheritance
// Base class - what all vehicles have in common class Vehicle { protected brand: string; protected year: number; protected color: string; constructor(brand: string, year: number, color: string) { this.brand = brand; this.year = year; this.color = color; } public getInfo(): string { return `${this.year} ${this.color} ${this.brand}`; } public start(): void { console.log(`${this.getInfo()} is starting... `); } } // Car class extends Vehicle - inherits all Vehicle properties and methods class Car extends Vehicle { private numberOfDoors: number; private fuelLevel: number; constructor(brand: string, year: number, color: string, doors: number) { super(brand, year, color); // Call parent constructor this.numberOfDoors = doors; this.fuelLevel = 100; } // New method specific to cars public honk(): void { console.log(`${this.getInfo()} says BEEP BEEP! `); } // Override parent method with car-specific behavior public start(): void { if (this.fuelLevel > 0) { console.log(` Starting ${this.getInfo()}... Engine running!`); } else { console.log(` ${this.getInfo()} needs fuel to start!`); } } public drive(distance: number): void { const fuelUsed = distance / 10; // 10 miles per fuel unit if (this.fuelLevel >= fuelUsed) { this.fuelLevel -= fuelUsed; console.log(` Drove ${distance} miles. Fuel remaining: ${this.fuelLevel.toFixed(1)}`); } else { console.log(" Not enough fuel for this trip!"); } } } // Motorcycle class also extends Vehicle class Motorcycle extends Vehicle { private hasSidecar: boolean; constructor(brand: string, year: number, color: string, sidecar: boolean = false) { super(brand, year, color); this.hasSidecar = sidecar; } public wheelie(): void { console.log(` ${this.getInfo()} is doing a wheelie! 🤸‍♂️`); } public start(): void { console.log(` ${this.getInfo()} roars to life! VROOM VROOM!`); } } // Using our classes const myCar = new Car("Toyota", 2023, "Blue", 4); const myBike = new Motorcycle("Harley Davidson", 2022, "Black", false); myCar.start(); // Car-specific start myCar.honk(); // Car-specific method myCar.drive(50); // Car-specific method myBike.start(); // Motorcycle-specific start myBike.wheelie(); // Motorcycle-specific method

Abstract Classes - Templates for Other Classes

Sometimes you want to create a template that other classes must follow, but you never want to create instances of the template itself.

Abstract classes
// Abstract class - can't be instantiated directly abstract class Animal { protected name: string; protected age: number; constructor(name: string, age: number) { this.name = name; this.age = age; } // Concrete method - all animals can do this public sleep(): void { console.log(`${this.name} is sleeping... `); } // Abstract method - each animal type must implement this differently abstract makeSound(): void; abstract move(): void; } class Dog extends Animal { private breed: string; constructor(name: string, age: number, breed: string) { super(name, age); this.breed = breed; } makeSound(): void { console.log(`${this.name} the ${this.breed} says WOOF! `); } move(): void { console.log(`${this.name} runs happily! `); } fetch(): void { console.log(`${this.name} fetches the ball! `); } } class Bird extends Animal { private canFly: boolean; constructor(name: string, age: number, canFly: boolean = true) { super(name, age); this.canFly = canFly; } makeSound(): void { console.log(`${this.name} chirps melodiously! `); } move(): void { if (this.canFly) { console.log(`${this.name} soars through the sky! ✈️`); } else { console.log(`${this.name} walks on the ground! 🚶‍♂️`); } } } // Using the classes const myDog = new Dog("Buddy", 3, "Golden Retriever"); const myBird = new Bird("Tweety", 1, true); myDog.makeSound(); // WOOF! myDog.move(); // runs happily myDog.fetch(); // Dog-specific method myBird.makeSound(); // chirps myBird.move(); // soars through sky // This would NOT work: // const animal = new Animal("Generic", 1); // ❌ Error! Can't instantiate abstract class

Modules - Organizing Your Code Like a Pro

📚 Modules are Like School Subjects

Imagine if all your school subjects were taught in one giant room with no organization - math, science, English, history all mixed together! That would be chaos. Modules help organize your code like separate classrooms, each with a specific purpose and clear boundaries.

Why Do We Need Modules?

As your projects grow, putting everything in one file becomes a nightmare. Modules help you:

  • Organize code - Keep related functions together
  • Encapsulation - Hide internal details
  • ♻ Reusability - Use code in multiple places
  • Collaboration - Team members can work on different modules
  • Debugging - Easier to find and fix issues

Creating Your First Module

Let's build a simple math utilities module!

mathUtils.ts - Your first module
// mathUtils.ts - A module for math operations // Export individual functions export function add(a: number, b: number): number { return a + b; } export function subtract(a: number, b: number): number { return a - b; } export function multiply(a: number, b: number): number { return a * b; } export function divide(a: number, b: number): number { if (b === 0) { throw new Error("Cannot divide by zero!"); } return a / b; } // Export a constant export const PI = 3.14159; // Export a class export class Calculator { private history: string[] = []; add(a: number, b: number): number { const result = a + b; this.history.push(`${a} + ${b} = ${result}`); return result; } getHistory(): string[] { return [...this.history]; // Return a copy } clearHistory(): void { this.history = []; } } // You can also export an interface export interface MathOperation { operand1: number; operand2: number; operator: string; result: number; }
